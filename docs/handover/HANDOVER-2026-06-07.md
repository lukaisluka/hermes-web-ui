## 一、项目概述

### 1.1 产品定位

**Poiera** 是一个基于 Hermes Agent 的 Web UI 管理面板，用于管理和操作 Hermes Agent 的各种功能。项目从上游 `hermes-web-ui` 完全分叉，采用独立的产品路线。

**核心定位**：
- 纯 Web UI 产品（移除桌面版）
- 支持 npm 和 Docker 部署
- 三级权限体系：`super_admin` | `admin` | `user`
- 多 Profile 业务隔离

### 1.2 技术栈

| 层级 | 技术 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Naive UI + Pinia |
| 后端 | Koa + TypeScript + SQLite |
| 测试 | Vitest (单元/集成) + Playwright (E2E) |
| 运行时 | Hermes Agent (Python) |

### 1.3 仓库结构

```
packages/
├── client/          # Vue 3 前端
├── server/          # Koa 后端 API
├── skills/          # 内置 Skills
└── website/         # 项目官网
tests/
├── client/          # 前端单元测试
├── server/          # 后端单元测试
├── shared/          # 共享测试工具
└── e2e/             # Playwright E2E 测试
docs/
├── security/        # 安全规格文档
├── superpowers/     # 实施计划
└── harness/         # 开发流程文档
```

## 三、权限模型 (RBAC)

### 3.1 信任模型

```
super_admin  -- 全局产品和部署管理员
    └── admin    -- 受信任的宿主机操作员，权限限于被授权的 Profiles
        └── user -- 不受信任的协作用户
```

**重要原则**：
- Profile 隔离用于业务数据分区和防止误操作，**不防御恶意 admin**
- admin 可配置任意本地 MCP 命令和外部 Skill 目录，这些能力可访问宿主资源
- 每个 Profile 作用域请求必须重新验证数据库授权，JWT 缓存和前端可见性不是授权边界

### 3.2 全局角色权限矩阵

| 能力 | super_admin | admin | user |
|---|:---:|:---:|:---:|
| 管理用户/角色/状态/密码/Profile 分配 | ✅ All | ❌ | ❌ |
| 创建/删除/导入/重命名 Profile | ✅ | ❌ | ❌ |
| 管理 Profile 配置和资源 | ✅ All | ✅ 授权 Profiles | ❌ |
| 更改 Profile 头像和重启运行时 | ✅ All | ✅ 授权 Profiles | ❌ |
| 重启全局 Gateway 或管理全局安全/部署 | ✅ | ❌ | ❌ |
| 更改自己的头像和密码 | ✅ | ✅ | ✅ |
| 更改用户名 | ✅ | ❌ | ❌ |

### 3.3 Skills 和 MCP 权限

| 能力 | super_admin | admin | user |
|---|:---:|:---:|:---:|
| 完全管理 Skills/MCP | ✅ All | ✅ 授权 Profiles | ❌ |
| 读取 Skill 描述和脱敏状态 | ✅ | ✅ | ✅ 当前 Profile |
| 读取 Skill 源码 | ✅ | ✅ | ❌ |
| 修改配置 | ✅ | ✅ | ❌ |

**安全规则**：
- 凭据始终脱敏，管理员只能替换/删除，不能读取明文
- 高风险 MCP 连接变更自动禁用并断开
- 新建/更新/恢复/复制/回滚的 Skill 默认禁用
- 保留最近 3 个版本（可配置）
- 删除进入 30 天回收站
- MCP 凭据不跨 Profile 复制

### 3.4 Chat 和 Group Chat 权限

**普通 Chat**：
- 内容仅对会话所有者可见
- 管理员只能看到创建者、时间戳、token 用量，**不能读取内容**
- 无主历史会话仅 `super_admin` 可见元数据，可分配给授权用户

**Group Chat**：
- 房间绑定一个 Profile，只能使用该 Profile 的 Agents
- 用户看到自己创建或加入的房间
- 房主管理配置、成员、Agent、删除
- 管理员可查看元数据，但必须加入房间才能读取消息
- 管理员加入/退出产生系统消息和审计事件
- 房主失去 Profile 权限 → 房间进入无主冻结状态，聊天继续，管理操作冻结

### 3.5 Files / Jobs / Kanban 权限

**文件**：
- 非敏感 Profile 文件为共享协作数据
- 敏感文件（.env, auth.json）**所有角色禁止通过 Web UI 读写**，仅显示脱敏状态/元数据
- 普通文件保留 30 天版本历史

**Jobs**：
- Profile 成员可见
- 仅创建者和管理员可管理或读取执行输出
- 所有者失去 Profile 权限 → Job 暂停，等待管理员转移所有权

**Kanban**：
- Profile 成员可见 Boards
- 用户可创建 Boards
- 成员可编辑自己创建或被分配的任务
- 所有成员可派发 Agent 工作
